# 客户端协议（所有客户端共用的唯一契约）

后端只通过这份协议和客户端对话。Flutter App（安卓/iOS）、网页版都按它实现，互不依赖。
改协议 = 先改这份文档和 `backend/app/blocks.py`，再改各端。机器可读版本：`GET /openapi.json`。

## 1. 鉴权
- `POST /api/auth/login` `{username, password}` → `{token}`（JWT）
- `GET /api/auth/me` → `{username}`（当前主人；“我的”页页头身份行用。老服务器没有 → 客户端只显示服务器域名）
- REST：请求头 `Authorization: Bearer <token>`
- WebSocket、图片/下载地址（带不了请求头）：`?token=<token>`
- 401 → 客户端清掉 token 回登录页

## 2. 聊天（WebSocket `/ws?token=`）

> 客户端约定：连接断了就退避重连；断线期间用户发的消息在客户端标“待发送”，连上再发 `user.message`；回复中途断线时，连上后 `turn.resume` 续传（v1.61，见下；老服务器则 `GET /api/conversations/{id}` 补全）。`approval.reply`、`form.reply`、`message.regenerate` 不排队。服务器按到达顺序一轮接一轮处理（不会丢掉刚结束时立刻发来的下一条）。
> **v1.61 断线续传**（backend/app/live_turns.py）：一轮不再绑在连接上。服务器 → 客户端的一轮事件（message.start … message.done / message.stopped / error）都多带 `turn_id`（这一轮）和 `seq`（从 1 起连续）；老客户端忽略即可。断线 = 只是退订，回答照常写完并落库；所有订阅连接都断开后最多再跑 `TURN_OFFLINE_MINUTES`（默认 30，0 = 旧行为断线即停）分钟，到点按“停止”收尾（`status: "stopped"`）；结束后保留 120 秒。同一对话的轮次按到达顺序排队（不论来自哪条连接），不同对话互不等待。`message.cancel` 带 `conversation_id` 时任何连接都能停那个对话正在跑的轮次。
> 续传：客户端 → `turn.resume {turn_id?, conversation_id?, after?: int}`。带 `turn_id`（断线前在看的）→ 补发 `seq > after` 的事件（哪怕已结束，还在保留期就补到 message.done）；只带 `conversation_id`（打开对话 / 重连时“旁观”）→ 只接正在跑或排队的轮次，从 seq 1（message.start）起补，已结束的不重放（GET 里已有）。服务器先回 `turn.resumed {turn_id, conversation_id, live, ended?, seq?, gap?}`：`live: false` = 没这轮（重启 / 过了保留期 / 对话对不上），以 GET 为准；`gap: true` = 游标早于服务器留的日志（每轮留最近 2000 条），随后发 `turn.snapshot {turn_id, seq, conversation_id, message: {blocks, steps}}`（这一轮到 seq 为止折叠好的块与活动步骤，客户端整份替换生成中的那条；没有就新建），再补其后的事件。客户端按 (turn_id, seq) 丢重复。`turn.resumed` 本身不是这一轮的事件，不参与去重。
> 心跳：客户端可发 `ping`，服务器回 `pong`（不带 turn_id）。客户端收到过 pong 后，60 秒什么都没收到就当线已死、主动重连（老服务器不回 pong，不启用）。重连退避 1 s 起翻倍、封顶 10 s、乘 0.5–1 随机抖动，连上满 60 s 才清零。
> 客户端慢到出站队列积压 5000 条：服务器以 1013 关闭这条连接，客户端重连后续传，不丢。
> 重新生成：客户端先在本地撤掉旧回复；收到 `error` 或回复开始前断线 → `GET /api/conversations/{id}` 以服务器为准。
> 停止：生成中发 `message.cancel`，停止键置灰，等服务器回 `message.done`（半截回复，`status: "stopped"`）或 `message.stopped`（还没吐字）再收尾；客户端不在本地先砍。断线 = 服务器照常写完（v1.61 起；没人看着超过 TURN_OFFLINE_MINUTES 才按停止收尾、半截落库为 `status: "stopped"`），重连后续传或 `GET` 能看到。v1.52：服务器进程在一轮中途被杀（崩溃 / OOM / 重启）时，这一轮的进度检查点会在服务器重新起来、或打开对话时变成一条 `status: "interrupted"` 的回复（半截内容保留；还在跑的步骤为 `stopped`，带 `note` 与 `code: "TOOL_OUTCOME_UNKNOWN"`）；客户端行尾标“服务器重启，回答被打断”。v1.56：预算用完收尾的回复 `status: "wrapped"`、原地打转被叫停的 `status: "looped"`（都会出现在 message.done 和 GET 里，内容完整但事没做完）；客户端行尾标说明，最后一条没正常说完（stopped / interrupted / wrapped / looped）的回复下给“继续”，点了就是发一条普通的 `user.message`（text “继续”），服务器在下一轮历史里附对应说明。老客户端不认识的 status 当正常说完。v1.57：被打断的回复在服务器端还带着工具轨迹（只给模型重放，不上协议，客户端无改动）。
> 复制：纯客户端，把回复的块转成 Markdown（text 原样、code 加围栏、table 转 Markdown 表、links 列表；审批/浏览器等过程卡片不复制）。
> 编辑：只能改最后一条用户消息（已在服务器上、不在生成中）。客户端先本地改气泡、撤掉后面的回复，再用 `message.start.user_message` 覆盖；被拒/断线同“重新生成”。

## 3. 消息块（`blocks.py` 是定义源）
每条消息 = `blocks: Block[]`，按 `type` 区分。客户端遇到不认识的 type 必须忽略，不能崩。
| type | 字段 |

## 5. 客户端约定
- 服务器地址由用户在登录页填写（自建，没有固定域名）
- 错误体：`{detail: string}`，直接展示给用户
- 工具轨迹（v1.55）：服务器在消息上另存 `trace`（模型下一轮看的工具调用 + 截短结果），只在服务器内部用，**不出现在任何协议消息里**；客户端无需改动
- 时间：ISO 8601 带时区（v1.18 起服务端所有 datetime 都经 app/wire_time.py 出口，SQLite 读回的无时区值按 UTC 补偏移，不再有无偏移字符串）；展示用用户本地时区
- 新消息提醒（没有推送时）：回到前台立刻、前台时每 2 分钟拉一次 `/api/inbox`；`latest.id` 变了且未读数增加 → 端内横幅 + Home 角标。后台不轮询（省电、省钱）

## 授权回跳（OAuth）
第三方回调 `GET /api/oauth/callback`（公开，靠签名 state 验真；state 里记着发起端 `client`，只能是 `web` / `app`）。结果统一是同一条路由 `/me/connectors` 加查询参数 `connected=<provider>` 或 `error=<原因>`：
- `web`：302 到 `/#/me/connectors?…`
- `app`：返回一个小页面，自动跳 `<APP_SCHEME>://app/me/connectors?…`（默认 scheme `myassistant`），并给“回到 App”按钮兜底（有的浏览器不允许无手势跳自定义 scheme）。App 用系统深链接收，go_router 直接把 path+query 当路由打开。

- v1.60：同一步里的只读工具调用可能并行，`tool.status` 会出现多个同时 `running` 的步骤（按 step id 合并，客户端已支持）；协议无新字段。
